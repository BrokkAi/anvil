Evidence rules, in strength order:

A green command counts only for behaviors its selected tests actually assert: confirm in the terminal_test_patch that some assertion would fail if this contract were violated. A build proves compilation; a race detector proves absence of data races, not liveness or blocking behavior; a test that blocks forever proves nothing until something asserts it returns.

Quote the decisive lines in the row; a file name alone is not inspection evidence. Use inspection evidence only for contracts a reader can fully verify without running anything.

3. Candidate claims are never evidence. A summary asserting a requirement is met, a requirement checklist authored by the candidate, or a test name that sounds relevant, with no ledger or quoted-code backing, leaves the row unverified.

Unblocking contracts get the strictest treatment. A test that wakes P by such means verifies only that P notices a flag after being woken, not that X unblocks P; the row is unverified. Inspection evidence for these contracts must quote the affirmative wake path X triggers on the already-blocked waiter — an abort handler that rejects or errors the pending read itself, controller.error() on the awaited stream, a condition-variable broadcast, closing the channel or pipe the waiter blocks on — and must show X can reach that path while P is blocked: a flag tested inside a read or write loop wakes nothing, and a mutex held across a blocking wait prevents any unblocking path that needs the same mutex from ever running.
